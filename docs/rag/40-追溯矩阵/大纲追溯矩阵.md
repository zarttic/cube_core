### 4.1 汇总：8 条内部接口的真实形态

| 形态 | 条数 | 接口 |
| --- | --- | --- |
| 真正的 WEB 服务接口，方向与大纲一致 | 3 | `NBJK-003`、`NBJK-006`、`NBJK-007` |
| 有真实实现、方向一致，但是进程内 store/ingest 函数（非 HTTP） | 1 | `NBJK-004` |
| 有实现但**方向与大纲相反或只有一侧** | 3 | `NBJK-001`、`NBJK-002`、`NBJK-008` |
| 经 SDK 进程内调用（非 HTTP） | 1 | `NBJK-005` |

**核心结论**：大纲对 `NBJK-001`/`002`/`008` 三条都写明「接口类型：WEB服务」，
但代码中**不存在这些 WEB 接口**，三个子系统之间是通过**直连同一套 OpenGauss 库表**耦合的：

- 共享库 `cube_v3`：② 写 `partition_tiles`/`partition_grid_cells`/`partition_indexes`，③ 直读
- 共享库 `cube`（schema `test`）：③④ 写 `compute_jobs`/`download_orders`/`compute_applications`，⑤ 直读并回写

这种耦合在功能上能跑通，但与大纲的接口口径、以及「松耦合、可独立部署」的设计意图不一致。
**库表结构一旦变更就会同时影响两侧**，且没有接口层可以做版本兼容、鉴权、限流与失败重试。
是否要把这三条改造成真正的 WEB 接口，属于需要需求方决策的事项。
