# 操作员权限体系接入说明

> 适用对象：需要在本系统（后台管理系统）中给操作员赋权限、或在自己子系统里按权限控制页面与接口的其它子系统开发者。
>
> 核心一句话：**权限码是“模块:操作”的字符串**，存在数据库（个人补充权限 + 岗位模板），登录时由后端计算成“生效权限”放进 `user.permissions` 返回；前端用它控制显示，后端用它做接口鉴权。

---

## 一、权限模型

### 1.1 权限码格式

`模块名:操作档位`，操作档位分三档：

| 档位 | 含义 |
|---|---|
| `view` | 查看 |
| `operate` | 操作 |
| `approve` | 审批 |

示例：`order_manage:view`（订单管理-查看）、`data_import:operate`（数据载入-操作）、`user_manage:approve`（用户管理-审批）。

### 1.2 权限目录（当前全量 19 个权限码）

| 模块 | 权限码 | 说明 |
|---|---|---|
| 用户管理 | `user_manage:view` / `user_manage:operate` / `user_manage:approve` | 用户列表、增删改、密码重置、等级审批 |
| 资源配额 | `resource_schedule:view` / `operate` / `approve` | 配额申请、使用率、配额修改、审批 |
| 安全审计 | `security_audit:view` | 行为审计日志、登录状态监测 |
| 系统配置 | `system_config:view` / `system_config:operate` | 系统统计/配置 |
| 订单管理 | `order_manage:view` / `order_manage:operate` | 订单列表、详情、取消、审批、批量操作 |
| 数据载入 | `data_import:view` / `data_import:operate` | ARD 数据载入、剖分、格网模型与编码 |
| 存储管理 | `storage:view` / `storage:operate` | 存储查看与操作 |
| 团队管理 | `team_manage:view` / `operate` / `approve` | 团队列表、解散、创建/退出审批 |
| 监控中心 | `monitor:view` | 瓦片监测、系统统计 |

> 约定：**每个权限码只归属一种操作员岗位**，各操作员之间权限互不交叉。

### 1.3 岗位模板（内置 6 个）

| 模板编码 | 模板名称 | 权限码 |
|---|---|---|
| `data_operator` | 数据操作员 | `data_import:view`、`data_import:operate` |
| `order_auditor` | 订单审核员 | `order_manage:view`、`order_manage:operate` |
| `user_admin` | 用户管理员 | `user_manage:view`、`user_manage:operate`、`user_manage:approve` |
| `resource_admin` | 资源管理员 | `resource_schedule:view/operate/approve`、`team_manage:view/operate/approve` |
| `monitor_auditor` | 监控审计员 | `security_audit:view`、`monitor:view` |
| `system_configurator` | 系统配置员 | `system_config:view`、`system_config:operate` |

### 1.4 生效权限计算公式

```
操作员生效权限 = 岗位模板权限 ∪ 个人补充权限
超级管理员      = 全部权限（恒等）
```

数据库存放位置：

| 表/字段 | 内容 |
|---|---|
| `users.admin_permissions` (JSON) | 个人补充权限码数组 |
| `users.operator_template_id` (外键) | 绑定的岗位模板 ID |
| `permission_templates.permissions` (JSON) | 模板自带的权限码数组 |
| `users.is_operator` / `users.is_super_admin` | 身份标志 |

## 二、怎么获取操作员的权限

### 2.1 登录接口

```
POST /api/login
Content-Type: application/json

{
  "username": "op_data",
  "password": "123456",
  "role": "操作员"
}
```

响应中的 `user.permissions` 就是该操作员的**生效权限**：

```json
{
  "access_token": "eyJ...",
  "user": {
    "username": "op_data",
    "role": "操作员",
    "is_operator": true,
    "operator_template_id": 1,
    "admin_permissions": [],
    "permissions": ["data_import:operate", "data_import:view"]
  }
}
```

### 2.2 已登录后获取当前用户权限

```
GET /api/me
Authorization: Bearer <access_token>
```

返回同样包含 `permissions` 字段（后端实时计算，改权限后无需重新登录也能拿到最新值）。

> 注意：**JWT（access_token）里只有身份标志**（`sub`、`role`、`user_id`、`is_operator`、`is_super_admin`），**没有权限码**。权限码必须通过登录响应或 `/api/me` 获取。

## 三、怎么给操作员赋权限

以下接口均需**超级管理员**调用（`Authorization: Bearer <超管token>`）。

### 3.1 创建操作员并绑定模板

```
POST /api/admin/operators
Content-Type: application/json
Authorization: Bearer <超管token>

{
  "username": "op_new",
  "email": "op_new@example.com",
  "password": "123456",
  "template_id": 1,                     // 岗位模板 ID，不绑模板传 null
  "extra_permissions": ["monitor:view"]  // 个人补充权限，模板之外可多选
}
```

响应：`{"message": "操作员创建成功", "user_id": 23}`

### 3.2 修改操作员的模板 / 补充权限

```
PUT /api/admin/operators/{user_id}/template
Content-Type: application/json
Authorization: Bearer <超管token>

{
  "template_id": 1,                          // null 表示解除模板
  "extra_permissions": ["order_manage:view"] // 覆盖式写入个人补充权限
}
```

### 3.3 查看可用的岗位模板

```
GET /api/admin/permission-templates
Authorization: Bearer <超管token>
```

返回模板列表（`id`、`code`、`name`、`permissions`）。

### 3.4 修改用户角色（把普通用户改成操作员等）

```
PUT /api/admin/users/{user_id}/role
Content-Type: application/json
Authorization: Bearer <超管token>

{ "role": "操作员" }
```

角色可选值：`普通用户`、`高级用户`、`科学家团队`、`操作员`、`管理员`。改成“操作员/管理员”时后端会自动同步 `is_operator = true`。

## 四、子系统里怎么用权限码

### 4.1 前端：按权限控制页面显示

前端拿到 `user.permissions` 后存起来，用“是否包含某个权限码”来判断：

```js
// 判断是否有“订单管理-查看”权限
const canManageOrders = userInfo.permissions.includes('order_manage:view')
```

本系统的用法（Vue store）：

```js
const can = (perm) => userInfo.permissions.includes(perm)
// 超管恒为 true
```

然后页面导航、按钮、模块页签都用 `can('xxx:view')` / `can('xxx:operate')` 控制显隐。

### 4.2 后端：按权限做接口鉴权

**不能只靠前端隐藏**，后端每个接口必须校验：

```python
from fastapi import Depends
from core.security import require_permission
from core.permissions import PERMISSION_ORDER_MANAGE_OPERATE

@router.post("/orders/{order_no}/cancel")
async def cancel_order(
    order_no: str,
    current_user = Depends(require_permission(PERMISSION_ORDER_MANAGE_OPERATE)),
):
    ...
```

如果子系统与主系统共享代码库，可以直接复用：

- `get_effective_permissions(db, user)`：计算生效权限；
- `has_effective_permission(db, user, "order_manage:view")`：判断单个权限；
- `require_permission(PERMISSION_XXX)`：FastAPI 依赖注入式鉴权。

如果子系统独立部署、不共享代码，推荐做法：

1. 用户登录/进入子系统时，调用 `GET /api/me`（带主系统 token）拿到 `permissions`；
2. 子系统后端把 `permissions` 绑定到会话，并在每个接口里用同一个权限码目录校验；
3. 权限码字符串与主系统保持完全一致。

## 五、子系统要新增自己的权限码怎么办

1. 在主系统 `backend/app/core/permissions.py` 的 `ALL_PERMISSIONS` 里注册新码，例如：

```python
PERMISSION_XXX_VIEW = "xxx:view"
PERMISSION_XXX_OPERATE = "xxx:operate"
```

2. 建一个岗位模板（或给具体操作员配个人补充权限）：

```python
PermissionTemplate(
    code="xxx_operator",
    name="XX操作员",
    permissions=[PERMISSION_XXX_VIEW, PERMISSION_XXX_OPERATE],
)
```

3. 前端在 `PERMISSION_OPTIONS` / `PERMISSION_LABELS` 里加上新权限码的展示名，否则会显示成原始码。

4. 注意：**保持“每个权限码只归属一种岗位”的约定**，避免两个操作员之间权限交叉。

## 六、代码示例

### 6.1 curl：登录拿权限

```bash
curl -X POST http://<host>:6000/api/login \
  -H "Content-Type: application/json" \
  -d '{"username":"op_data","password":"123456","role":"操作员"}'
```

### 6.2 Python：创建操作员并绑定模板

```python
import requests

admin_login = requests.post("http://<host>:6000/api/login",
    json={"username": "admin", "password": "123456", "role": "管理员"})
token = admin_login.json()["access_token"]

r = requests.post("http://<host>:6000/api/admin/operators",
    headers={"Authorization": f"Bearer {token}"},
    json={
        "username": "op_new",
        "email": "op_new@example.com",
        "password": "123456",
        "template_id": 1,                       # 数据操作员模板
        "extra_permissions": ["monitor:view"],
    })
print(r.json())
```

### 6.3 Python：查询操作员当前生效权限

```python
op_login = requests.post("http://<host>:6000/api/login",
    json={"username": "op_data", "password": "123456", "role": "操作员"})
print(op_login.json()["user"]["permissions"])
```

## 七、注意事项

1. **改了权限要重新登录才生效**（登录时计算一次生效权限）；或让用户重新调用 `GET /api/me` 刷新。
2. **越权校验必须在后端做**，前端隐藏只是体验，不能作为安全边界。
3. 权限码大小写敏感，统一小写 `模块:操作`。
4. 数据库字段是 JSON 数组，直接改库后需保证 `operator_template_id` 指向真实存在的模板。
5. 子系统使用主系统 token 时，注意 token 过期时间（默认 15 分钟），过期后调用 `/api/login` 或刷新机制换新。
